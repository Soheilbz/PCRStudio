## Scope

KASP uses two competing allele-specific forward primers and one common reverse primer. In the standard LGC tail set, the FAM primer tail is `5'-GAAGGTGACCAAGTTCATGCT-3'` and the HEX primer tail is `5'-GAAGGTCGGAGTCAACGGATT-3'`; these tails are incorporated into the amplicon and subsequently addressed by the corresponding universal FRET cassettes. The tail is an ordering and readout component, not part of the genomic annealing segment, and the assay requires a declared instrument/channel interpretation ([Cuppen](https://pubmed.ncbi.nlm.nih.gov/21357174/), [Ramirez-Gonzalez et al.](https://onlinelibrary.wiley.com/doi/full/10.1111/pbi.12281), [LGC end-point genotyping compiled manual](https://biosearchassets.biosearchtech.com/assetsv6/manual_end-point-genotyping.pdf)).

The module owns tail identity, allele-specific geometry, reporter/channel mapping and cluster-control requirements. It must not treat a Primer3 score or a sequence match as a fluorescent genotype call; LGC requires a completed endpoint read and cluster interpretation, and its chemistry is currently an endpoint rather than real-time assay ([Cuppen](https://pubmed.ncbi.nlm.nih.gov/21357174/), [LGC KASP genotyping protocols](https://www.biosearchtech.com/products/oligos-probes-and-primers/kasp-genotyping-assays/running-kasp-genotyping-reactions)).

The runtime profile's default polymerase is `taq-standard`; this is an implementation baseline for the named profile, not a universal KASP chemistry claim ([LGC KASP chemistry user guide](https://biosearchassets.biosearchtech.com/assetsv6/KASP-genotyping-chemistry-User-guide.pdf)).

### Supported polymorphism modes and topology boundary

Current LGC sequence-submission guidance explicitly states that KASP chemistry can be used for SNPs, indels, and **presence/absence of a target DNA sequence (`plus/minus` assay)**. PCRStudio does not infer that every vendor-supported event shares one primer geometry: its current `biallelic-genotype` implementation is the single-anchor SNV/MNV branch, while insertion/deletion/complex/presence–absence events use the separate junction-aware `plus-minus-presence-absence` branch. This is an implementation boundary, not a claim that the vendor chemistry itself is limited to those categories ([LGC sequence submission](https://www.biosearchtech.com/support/resources/starting-a-genotyping-project/sequence-submission)).

A canonical record therefore requires `assay_mode = biallelic_genotype | plus_minus_presence_absence`. For the current PCRStudio `biallelic_genotype` branch, exact SNV/MNV REF/ALT is retained and a single differing anchor is used. For `plus_minus_presence_absence`, insertion/deletion/complex or presence–absence REF/ALT constructs are reconstructed explicitly and the target-definition, positive/negative controls and call semantics remain separate. Presence–absence uses the submitted reference as the present allele (`REF = present sequence`, `ALT = empty`); when the submitted reference is the absence allele, the event is represented as an insertion. The module must not automatically require Hardy–Weinberg/MAF assumptions or reinterpret a two-state presence/absence assay as the usual three diploid genotype clusters. LGC's public page establishes chemistry support for this mode but does not publish one universal primer topology or cluster cutoff for every plus/minus implementation, so PCRStudio must not invent one ([LGC sequence submission](https://www.biosearchtech.com/support/resources/starting-a-genotyping-project/sequence-submission)).

## Vendor protocol overlay: LGC Biosearch Technologies KASP

The LGC description defines the KASP assay mix as two competing allele-specific forward primers with distinct tail sequences plus one common reverse primer, and the readout as FAM/HEX endpoint fluorescence. LGC also describes the chemistry as singleplex and recommends a minimum final DNA concentration of `2.5 ng/µL` for its standard guidance; its FAQ defines the `61–55 °C` touchdown programme as the **standard** KASP cycling branch ([How KASP works](https://www.biosearchtech.com/how-does-kasp-work), [KASP Genotyping FAQs](https://www.biosearchtech.com/support/faqs/kasp-genotyping-assays)).

These values and channel rules are owned by the named LGC KASP chemistry. The experiment record must retain the master-mix/assay identity, DNA-input basis, instrument context, selected cycling branch and cluster-review state; the supplied documentation states that the current overlay emits the chemistry, DNA guidance, cycle/readout fields and an explicit unresolved note for instrument compatibility and cluster review, but it does not claim that either state has been measured. The `2.5 ng/µL` threshold and touchdown programme must not transfer to another allele-specific chemistry ([KASP Genotyping Protocols](https://www.biosearchtech.com/products/oligos-probes-and-primers/kasp-genotyping-assays/running-kasp-genotyping-reactions)).

The documented runtime contract states that, when `kasp_protocol=lgc-standard` is selected, a versioned protocol object is emitted containing the LGC standard `10 µL` reaction, `2.5 ng/µL` final-DNA guidance, `94 °C` activation, `61–55 °C` touchdown, `26` lower-temperature amplification cycles, FAM/HEX readout and the minimum NTC guidance. With no selection, the object is absent; the presence of KASP geometry alone never invents a wet-lab programme. This is a provenance overlay, not a prediction of cluster separation or a substitute for the current instrument-specific LGC protocol ([LGC KASP Genotyping FAQs](https://www.biosearchtech.com/support/faqs/kasp-genotyping-assays), [LGC KASP troubleshooting guide](https://biosearchassets.biosearchtech.com/assetsv6/KASP-troubleshooting-guide.pdf)).

The current LGC FAQ gives the standard thermal programme in full: `94 °C` activation for `15 min`; `10` touchdown cycles of `94 °C/20 s` followed by annealing/extension at `61–55 °C` for `60 s`, decreasing by `0.6 °C` per cycle; then `26` cycles of `94 °C/20 s` and `55 °C/60 s`. LGC also distinguishes `10 µL` reactions for 96-well plates from `5 µL` reactions for 384-well plates, and lists a `68–62 °C` touchdown alternative for assays with high GC content above `65%` ([LGC KASP Genotyping FAQs](https://www.biosearchtech.com/support/faqs/kasp-genotyping-assays)). These values belong to the named LGC KASP protocol and must remain separate from the software's allele-specific search envelope and from other fluorescent genotyping chemistries.

The historical LGC chemistry guide records at least `22` DNA samples for cluster analysis plus `2` NTCs on a 96-well plate or `4` NTCs on a 384-well plate. The current LGC FAQ instead states a minimum of `2` NTC wells per KASP assay per reaction plate; the active runtime follows that current web guidance while retaining the older plate-specific values as historical evidence. The current LGC FAQ gives the exact wet-DNA mix as `4.86 µL` DNA + `5 µL` `2X` KASP-TF Master Mix + `0.14 µL` KASP Assay Mix in a `10 µL` 96-well reaction, or `2.43 µL` DNA + `2.5 µL` master mix + `0.07 µL` assay mix in a `5 µL` 384-well reaction. The dry-DNA alternative replaces the DNA volume with `4.86 µL` or `2.43 µL` water, respectively, keeping the master mix at `1X` final. The preparation volume should include `10%` excess for pipetting, and the sealed plate is centrifuged at a minimum of `550 × g` ([LGC KASP genotyping chemistry user guide](https://biosearchassets.biosearchtech.com/assetsv6/KASP-genotyping-chemistry-User-guide.pdf), [LGC KASP Genotyping FAQs](https://www.biosearchtech.com/support/faqs/kasp-genotyping-assays)).

The same guide records the endpoint read contract: FAM excitation/emission `485/520 nm`, HEX `535/556 nm` and ROX `575/610 nm`; the plate must be below `40 °C` before reading. If clusters remain unresolved after the standard `36` PCR cycles, LGC permits recycling in increments of `3` cycles, up to `4` recycle steps (`12` additional cycles), with a read after each recycle. Completed plates may be held in a dark refrigerator at approximately `4 °C` for a maximum of `1 week` while additional reads or recycle steps are decided. These are instrument/protocol handling values, not genotype-call thresholds ([LGC KASP genotyping chemistry user guide](https://biosearchassets.biosearchtech.com/assetsv6/KASP-genotyping-chemistry-User-guide.pdf)).

The DNA-input guidance is genome-size dependent and must be preserved as a calculation, not just as a boolean “enough DNA” flag. LGC's rounded calculation example is based on a human genome size of approximately `3000 Mbp`: a `10 µL` reaction treated as `5 µL` DNA plus `5 µL` genotyping mix needs DNA at `5 ng/µL` to reach the recommended final concentration of `2.5 ng/µL`; the exact current assembly table uses `4.86 µL` DNA plus `5 µL` mix. For a genome larger than human, the guide scales the final concentration by `genome_size / 3000 Mbp`; its wheat example uses `15966 Mbp / 3000 Mbp = 5.3`, giving `13.25 ng/µL` final DNA. It does not recommend lowering the input for genomes smaller than human. These are LGC KASP sample-input rules and remain separate from the software's generic template fields ([LGC KASP Genotyping FAQs](https://www.biosearchtech.com/support/faqs/kasp-genotyping-assays)).

For high-throughput Array Tape, LGC publishes a separate KASP-TF V5.0 overlay that must never be merged with the standard `10/5 µL` plate record. With wet DNA, the illustrated reaction is `0.8 µL` DNA + `0.8 µL` `2X` master mix + `0.022 µL` `72X` assay mix, total `1.6 µL`; for `384` reactions with `20%` excess the corresponding master-mix and assay-mix volumes are `368.6 µL` and `10.14 µL`. With dried DNA, the mix is `0.8 µL` `1X` master mix + `0.011 µL` assay mix, total `0.8 µL`, and the illustrated `384`-reaction volumes are `368.6 µL` and `5.07 µL`. The Array Tape programme is `94 °C/15 min`, then `10` cycles of `94 °C/20 s` with a `65→57 °C` touchdown decreasing `0.8 °C` per cycle and `60 s` annealing/extension, followed by `26` cycles at `94 °C/20 s` and `57 °C/60 s`; these settings are explicitly optimized for Array Tape and not standard PCR plates ([LGC KASP-TF V5.0 Master Mix manual](https://biosearchassets.biosearchtech.com/assetsv6/manual_kasp-tf-master-mix.pdf)).

For the Array Tape IntelliQube in-line branch, the vendor records `35` Stage-3 cycles after the `10`-cycle touchdown, for `45` total cycles, with a read at the end of each Stage-3 cycle; this is still endpoint genotyping, not real-time quantification. The `61–55 °C` branch uses `93.5 °C/15 min`, `93.5 °C/20 s` for each touchdown cycle and a `0.6 °C` decrement, while the alternate `65–57 °C` branch uses the same `93.5 °C/20 s` denaturation and a `0.8 °C` decrement. The manual maps ROX to passive reference, FAM to the x-axis and HEX (or VIC where the dye set requires it) to the y-axis ([LGC KASP-TF V5.0 Master Mix manual](https://biosearchassets.biosearchtech.com/assetsv6/manual_kasp-tf-master-mix.pdf)).

The standard LGC plate manual also specifies the optional qPCR read stage as `30 °C/60 s`; if the programme is run on a Peltier block or Hydrocycler, only Stages 1–3 are needed, but the plate must still be cooled below `40 °C` before reading. LGC's instrument table assigns Low, Standard, High or Fluidigm ROX mixes by instrument family, so `qpcr-dye` is not enough provenance for a reproducible run: the record must retain the instrument model, ROX branch and software protocol used ([LGC KASP genotyping chemistry user guide](https://biosearchassets.biosearchtech.com/assetsv6/KASP-genotyping-chemistry-User-guide.pdf), [LGC KASP genotyping protocols](https://www.biosearchtech.com/products/oligos-probes-and-primers/kasp-genotyping-assays/running-kasp-genotyping-reactions)).

Published KASP implementations demonstrate that volume and cycling values are not universal even when the same LGC chemistry family is used. Ramirez-Gonzalez et al. used a `4 µL` 384-well reaction containing `2 µL` template at `10–20 ng` DNA, `1.944 µL` V4 `2X` KASP mix and `0.056 µL` primer mix; their primer mix used `46 µL` water, `30 µL` common primer and `12 µL` of each tailed primer at `100 µM`. Their programme used `95 °C/15 min`, a `65 °C` touchdown decreasing `1 °C` per cycle for `10` cycles, then `30` cycles at `57 °C`, with a further `5–10` cycles when clusters had not formed. This is a literature branch, not a replacement for the named LGC standard or Array Tape overlays ([Ramirez-Gonzalez et al.](https://onlinelibrary.wiley.com/doi/full/10.1111/pbi.12281)).

## KASP design, chemistry-version and calling boundaries

The public LGC sequence-submission workflow currently broadens the chemistry scope beyond ordinary biallelic SNP/indel genotyping by explicitly listing target presence/absence (`plus/minus`) assays. This is a **mode branch**, not evidence that the same reference/alternate fields, minor-allele-frequency criterion or three-cluster geometry are universally valid. A plus/minus record must state the target sequence that defines the positive state, the negative/reference state, the control materials and the instrument-specific call rule; if the exact primer/cassette topology is not supplied by the selected vendor protocol, the engine should mark it unresolved rather than infer it from the biallelic branch ([LGC sequence submission](https://www.biosearchtech.com/support/resources/starting-a-genotyping-project/sequence-submission)).

LGC separates design-only `KASP-by-Design (KBD)` assays from `KASP-on-Demand (KOD)` assays that are optimised and functionally validated in its genotyping laboratory. A runtime record must therefore retain the assay provenance and must not label a KBD assay as laboratory-validated merely because its sequence design passed in-silico filters ([LGC end-point genotyping compiled manual](https://biosearchassets.biosearchtech.com/assetsv6/manual_end-point-genotyping.pdf), [LGC KASP Genotyping FAQs](https://www.biosearchtech.com/support/faqs/kasp-genotyping-assays)).

LGC states that its proprietary `Kraken` software applies its own primer-design parameters, but does not publish a complete instrument-independent table of KASP primer length, Tm, GC, product-size or terminal-mismatch cutoffs on the public assay-design page. Accordingly, the `kasp_profile_*` values above are software search baselines, not recovered LGC rules; they must remain labelled as internal, configurable and experimentally defeasible rather than being presented as scientific KASP constants ([LGC assay design for KASP chemistry](https://oligos.biosearchtech.com/support/resources/starting-a-genotyping-project/assay-design-for-kasp-chemistry)).

For an LGC design submission, the current FAQ requests at least `50 bp` of sequence on each side of the polymorphism and recommends including up to `100 bp` per side when available; the compiled manual additionally documents SNPs, indels, MNVs and haplotypes. For an rs identifier, LGC says explicit sequence remains advisable so the requested context is unambiguous. The module should therefore retain both the accession/build and the explicit flanking sequence when available. NCBI's RefSNP documentation defines the RefSNP identifier, assembly placement and flanking-sequence fields, so an rsID without assembly/strand context is not sufficient provenance for primer orientation ([LGC KASP Genotyping FAQs](https://www.biosearchtech.com/support/faqs/kasp-genotyping-assays), [LGC end-point genotyping compiled manual](https://biosearchassets.biosearchtech.com/assetsv6/manual_end-point-genotyping.pdf), [NCBI dbSNP RefSNP documentation](https://www.ncbi.nlm.nih.gov/snp/docs/RefSNP_about/)).

For its own validated-assay service, LGC names four acceptance criteria: negative NTCs, three distinct genotype clusters, sample call rate greater than `90%`, and minor-allele frequency greater than `2%` unless the allele is known to be very rare. These are vendor service criteria, not universal statistical cutoffs; the software should expose them as provenance-labelled validation fields rather than silently turning them into a general KASP rule ([LGC assay design for KASP chemistry](https://oligos.biosearchtech.com/support/resources/starting-a-genotyping-project/assay-design-for-kasp-chemistry)).

The endpoint plot is assay- and plate-specific. LGC advises analysing at least `22` data points plus `2` NTCs per plot, keeping different assays and reaction plates on separate plots, checking comparable X/Y scaling, adding known positive controls where possible, and manually sense-checking automatic calls. This means the result model needs `plate_id`, `assay_id`, `ntc_status`, optional known-genotype controls, axis-scaling state and an explicit `no_call` outcome; fluorescence values from different assays or plates must not be pooled into one cluster model ([LGC analysis of end-point genotyping data using cluster plots](https://biosearchassets.biosearchtech.com/assetsv6/Analysis-of-KASP-genotyping-data-using-cluster-plots.pdf)).

The expected three-cluster geometry is conditional, not a call algorithm: FAM-positive homozygotes lie near the x-axis, HEX-positive homozygotes near the y-axis, heterozygotes near the centre, and NTCs near the origin only when the assay amplifies and the optical axes are comparable. LGC warns that automatic calling algorithms differ in robustness, that unreviewed auto-calls can be misinterpreted, and that different plates or assays should not be pooled. A cluster rule must consequently expose `no_call` for scattered, merged, origin-bound or extra-cluster points and preserve the manual-review decision ([LGC analysis of end-point genotyping data using cluster plots](https://biosearchassets.biosearchtech.com/assetsv6/Analysis-of-KASP-genotyping-data-using-cluster-plots.pdf), [LGC end-point genotyping compiled manual](https://biosearchassets.biosearchtech.com/assetsv6/manual_end-point-genotyping.pdf)).

LGC troubleshooting identifies practical failure modes that should remain visible in the audit record: inconsistent DNA quantity or quality, PCR inhibitors, poor dispensing, incorrect plate sealing or optical setup, homologous target sequence, primer-binding polymorphisms, excessive magnesium, and unequal allele-primer amplification can scatter clusters or move the heterozygote toward a homozygote. The documented remedies are assay- and chemistry-scoped—normalize or dilute DNA, inspect ROX as a dispensing check, redesign around homology, consider a magnesium titration, or use an alternative cycling branch—so a failed cluster should not be converted into a genotype by sequence plausibility alone ([LGC end-point genotyping compiled manual](https://biosearchassets.biosearchtech.com/assetsv6/manual_end-point-genotyping.pdf), [LGC KASP troubleshooting guide](https://biosearchassets.biosearchtech.com/assetsv6/KASP-troubleshooting-guide.pdf)).

Current LGC pages expose an important provenance distinction in validation thresholds. The assay-design page lists `>90%` call rate and `>2%` minor-allele frequency among its validated-assay criteria, whereas the current KASP FAQ says service projects should generally achieve `>95%` call rate, typically `>99%` in well-defined genomes such as human, and states that a KOD assay is normally not classed as validated unless it achieved `>95%` in-house (unless specifically requested otherwise). PCRStudio must preserve the source/context of each threshold rather than average or silently choose between them; they describe different service/validation contexts, not one universal genotype-call threshold ([LGC assay design for KASP chemistry](https://oligos.biosearchtech.com/support/resources/starting-a-genotyping-project/assay-design-for-kasp-chemistry), [LGC KASP Genotyping FAQs](https://www.biosearchtech.com/support/faqs/kasp-genotyping-assays)).

Non-traditional KASP applications require their own branch. A published methods chapter describes modified protocol/data-analysis approaches for rare alleles, pooled samples, tri-allelic loci and situations with more than three expected genotypes; in one reported pooled-seed application, a rare allele could be detected at a ratio as low as `1 in 200`. This is not a standard KASP limit of detection and must never be inherited by the ordinary biallelic profile; it is evidence that `rare_allele_or_complex_genotype` should be an explicit experimental mode with its own controls, calibration and call model ([Modifications of KASP Genotyping for Detection of Rare Alleles](https://pubmed.ncbi.nlm.nih.gov/36781642/)).

For polyploid material, an independent genotype reference is especially important: a wheat KASP validation study used artificial heterozygote mixtures spanning `9:1` to `1:9` allele ratios to expose false cluster calls and reported `1.1%` disagreement with the source SNP-chip calls despite `100%` call rates; it recommended independent sequencing-based accuracy checks. This is a species- and study-specific warning, not a universal KASP error rate, but it supports retaining heterozygote challenge material and concordance results in this module ([Overcoming polyploidy pitfalls](https://link.springer.com/article/10.1007/s00122-020-03608-x)).

Where KASP results are used in a regulated medical or accredited testing workflow, the relevant quality system is an additional scope layer rather than an LGC KASP rule: ISO 15189:2022 covers medical-laboratory quality and competence, ISO/IEC 17025:2017 covers competent testing laboratories, and the ACMG pharmacogenomic technical standard calls for accuracy, precision, analytical sensitivity/specificity, reportable range and documented concordance with expected results. The cited LGC manuals are marked for research use only and not for diagnostic procedures. The present profile therefore remains research-use/experimental unless that intended-use validation has been completed ([ISO 15189:2022](https://www.iso.org/standard/76677.html), [ISO/IEC 17025:2017](https://www.iso.org/standard/66912.html), [ACMG clinical pharmacogenomic testing and reporting standard](https://pubmed.ncbi.nlm.nih.gov/35177334/), [LGC KASP genotyping chemistry user guide](https://biosearchassets.biosearchtech.com/assetsv6/KASP-genotyping-chemistry-User-guide.pdf)).

The LGC FAQ also makes the chemistry-version boundary explicit: KASP Master Mix v3 is supplied at `3.6 mM` Mg²⁺ to give `1.8 mM` final, whereas v4 is supplied at `5 mM` to give `2.5 mM` final. The mix should be aliquoted, protected from light and stored for `1 week` at `4 °C` or `1 year` at `−20 °C`/`−80 °C`; LGC advises not exceeding `3` freeze–thaw cycles. These values belong to the named mix version and must not be substituted into another chemistry without an explicit protocol record ([LGC KASP Genotyping FAQs](https://www.biosearchtech.com/support/faqs/kasp-genotyping-assays)).

## Current LGC troubleshooting and homology overlay

The current LGC KASP troubleshooting guide adds two source-scoped branches that must not be promoted to generic KASP defaults. For SNPs in particularly high-GC regions, LGC states that `5–10%` DMSO in the final reaction can be beneficial and says to retain the standard `2.5 mM` MgCl2 final concentration for that DMSO branch. Separately, when a highly homologous locus threatens specificity, a base unique to the intended locus within `50 bp` on either side of the SNP can be used as an anchoring point by placing that unique base at the `3′` end of the common reverse primer. Both are troubleshooting strategies: neither proves genotype-cluster accuracy, and neither is appropriate as an automatic rule without the corresponding high-GC or homology condition ([LGC KASP troubleshooting guide](https://biosearchassets.biosearchtech.com/assetsv6/KASP-troubleshooting-guide.pdf)).

## EasyKASP empirical design profile — 2025

EasyKASP is retained as **peer-reviewed empirical KASP design evidence**, not as a generation-1 backend dependency. The study analysed `500` previously successful KASP primers and used the resulting distributions/rules in an Excel-VBA designer; it then reported successful amplification/genotyping for `80` SNP loci and `6` InDel loci in its validation set. The software itself is Windows/Excel VBA and GPL, so PCRStudio imports the source-scoped design evidence while keeping candidate generation in the local allele-aware/Primer3 pipeline ([EasyKASP article](https://pmc.ncbi.nlm.nih.gov/articles/PMC12717768/), [project source](https://github.com/zhangjian0603/KASP-primer-design)).

The paper's recommended genomic annealing-segment profile is: allele-specific primers `21–27 bp`, common primer `22–32 bp`; optimal GC `30–60%` with an allowed envelope `20–70%`; allele-specific Tm `57.5 ± 1.5 °C`, common-primer Tm `60.5 ± 1.5 °C`, specific-primer ΔTm `<1 °C`, with the common primer about `2 °C` higher; no `6` identical consecutive bases, no `4` consecutive complementary bases, no `3` or more SSR repeat units, and at least `4` base types. Its product geometry places the variation-to-common-primer distance `<30 bp` and total product `<100 bp`; its 3′ filter disallows `4` consecutive G/C and `5` consecutive A/T. These are **EasyKASP study-derived recommendations** and do not overwrite LGC's chemistry/version-specific guidance or PCRStudio's generic permissive search envelope ([EasyKASP](https://pmc.ncbi.nlm.nih.gov/articles/PMC12717768/)).

EasyKASP prints the empirical expression `Tm = 72 + 37.4 × GC% − 747/LEN` and states that it was optimized for the LGC KASP master mix. Its published VBA source computes `72 + (37.4 × GC_count − 747) / LEN`, which is algebraically equivalent to using `GC_fraction = GC_count/LEN` in the `37.4` term. PCRStudio therefore preserves the paper's printed notation **and** records the executable source semantics as `Tm = 72 + 37.4 × GC_fraction − 747/LEN`. It must never be substituted for Primer3/nearest-neighbour Tm in another assay or chemistry without an explicit, source-verified profile. The tool also requires at least `70 bp` of supplied flanking sequence and selects an initial allele-specific-primer strand by inspecting a `25 bp` neighbourhood, preferring GC near `45%` without repeated bases, then trying the opposite direction if design fails. That direction heuristic is a reproducible candidate-ordering precedent, not a biological hard gate ([EasyKASP](https://pmc.ncbi.nlm.nih.gov/articles/PMC12717768/)).

## Evidence

**R16 implementation disposition:** the historical chemistry/product-envelope blockers remain closed. The standard biallelic branch and a separate junction-aware `plus-minus` presence/absence branch are now executable under typed variant/protocol contracts. The plus/minus branch reconstructs the declared REF/ALT constructs and requires an allele-junction design rather than reinterpreting the event as an ordinary SNP. Endpoint FAM/HEX import is an evidence workflow: provider/software calls are preserved and assay/plate scatter geometry is displayed, but PCRStudio does not synthesize a universal cluster threshold or genotype call and does not claim Kraken-equivalent design ([LGC KASP sequence-submission guidance](https://www.biosearchtech.com/support/resources/starting-a-genotyping-project/sequence-submission), [LGC cluster-plot guidance](https://biosearchassets.biosearchtech.com/assetsv6/Analysis-of-KASP-genotyping-data-using-cluster-plots.pdf)).

The cited KASP literature and LGC manuals support universal-tail fluorescent genotyping, but they do not provide one instrument-independent cluster threshold, one universal primer success rate or one universal volume/cycling recipe across LGC plate, Array Tape, service and modified-literature branches. Those values remain module inputs tied to the chemistry, instrument, plate format and control panel ([Cuppen](https://pubmed.ncbi.nlm.nih.gov/21357174/), [LGC KASP genotyping chemistry user guide](https://biosearchassets.biosearchtech.com/assetsv6/KASP-genotyping-chemistry-User-guide.pdf), [LGC KASP-TF V5.0 Master Mix manual](https://biosearchassets.biosearchtech.com/assetsv6/manual_kasp-tf-master-mix.pdf), [Kalendar et al.](https://pmc.ncbi.nlm.nih.gov/articles/PMC8921500/)).

## R16 executable boundary

The canonical KASP records are in `contracts/chemistry/discriminating-protocols.json`. `lgc-standard` is retained only as historical compatibility; current source-limited protocol identity is explicit. The current PCRStudio biallelic branch accepts SNV/MNV single-anchor designs; insertion, deletion, complex replacement and presence–absence use the separate junction-aware plus/minus geometry. Presence–absence uses non-empty REF on the submitted reference and empty ALT; an alternate-only insertion is typed as `insertion`. The plus/minus branch reconstructs the declared allele constructs and seeks junction-aware allele discrimination rather than reusing SNP logic ([LGC KASP sequence submission](https://www.biosearchtech.com/support/resources/starting-a-genotyping-project/sequence-submission)).

Endpoint evidence accepts declared FAM/HEX measurements, plate/well/sample identity, controls and existing provider/software calls. The UI uses FAM on X and HEX on Y for review. PCRStudio does **not** infer a universal cluster boundary, does not auto-call unlabelled samples from a hidden threshold, and does not represent its design as proprietary Kraken-equivalent output. Call states such as `AA`, `AB`, `BB`, `no-call`, `weak` or `ambiguous` are evidence only when supplied or explicitly reviewed under a versioned calling workflow ([LGC KASP genotyping protocols](https://www.biosearchtech.com/products/oligos-probes-and-primers/kasp-genotyping-assays/running-kasp-genotyping-reactions)).
