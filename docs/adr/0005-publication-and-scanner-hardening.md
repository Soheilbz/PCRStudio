# ADR 0005 — Existing-repository publication and scanner hardening

Status: accepted implementation decision. Date: 2026-10-09.

The user explicitly requested replacing the existing public Soheilbz/PCRStudio repository with this fresh foundation as its first new version. Preserve the old source archive and a separately verified full repository/release backup before replacing published refs. The validation branch does not replace main until checks pass. Main protection retains actual qualification, Python/JavaScript CodeQL and dependency review; only the obsolete Rust context is removed because this platform has no Rust source.

Hosted CI uses canonical, immutable Docker Hub pins and standard build networking; local bootstrap retains its tested ECR/host-build configuration. Both registry profiles resolve to verified identical image payloads. These build-only choices do not change runtime networking, stored identities, secrets or namespace. They address actual anonymous ECR throttling and BuildKit entitlement failures without granting additional privileges.

CodeQL findings prompted concrete source hardening. Inline CSP permissions use a real HTML parser with source locations and hash original immutable script bytes; comments, quoted delimiters and external scripts do not confuse tag matching. The parser is a pinned build/test dependency, with no Node process in the edge runtime.

Secret files are restricted to 0440 under 0700 directories. App/migration/database processes receive only the required persisted supplementary group and individually selected read-only secret mounts. PostgreSQL starts directly as its image's 70:70 identity so first initialization retains that group; image-directory ownership and a genuinely empty database qualification prove fresh install compatibility. No host group membership, global Docker setting or stored secret value is changed.

The remaining `py/overly-permissive-file` finding for group read at `scripts/init_local.py` is a contextual false positive for this verified local topology. The group represents authorized non-root consumers of each explicitly mounted file; other host users cannot traverse the private parent directories. The source-owner tools container is a trusted operator and can read all locally generated secrets. This is intentional authorization, not a claim that secrets are hidden from the operator or Docker administrator. Docker documents [supplemental groups for shared-file access](https://docs.docker.com/reference/compose-file/services/#group_add) and [per-service read-only secret mounts](https://docs.docker.com/reference/compose-file/services/#secrets). File-backed Compose secrets retain source ownership and permissions.

Independent review checked real file metadata and ACLs, the mount selection, live process groups and the [CodeQL query implementation](https://github.com/github/codeql/blob/main/python/ql/src/Security/CWE-732/WeakFilePermissions.ql). This [medium-precision rule](https://codeql.github.com/codeql-query-help/python/py-overly-permissive-file/) flags nonzero group bits without modeling ancestor permissions or the authorized group. Alert-specific false-positive triage retains this evidence; the query and security-extended suite remain enabled. Operations checks enforce the topology, and initializer regressions prove tightening and preservation. Reassess the decision if directory permissions, mounts, process trust or deployment topology change. Production secret delivery is a separate release gate.
