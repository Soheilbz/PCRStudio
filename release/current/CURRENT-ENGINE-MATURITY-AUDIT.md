# CURRENT engine maturity audit

Deep scientific checks are organized by engine/domain, not by historical engine batches. The unified registry requires all 11 engines to have a profile and generated contract surface. Additional maturity guards protect method-specific numeric authority, tool roles, assay boundaries and fail-closed behavior for the engines whose contracts have deeper source assertions.

This distinction is intentional: registry uniformity is complete across all 11 engines; depth of assay-specific assertions can differ without creating a separate engine family or release namespace.
